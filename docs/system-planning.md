# 长牛回撤价值选股系统：产品与技术策划方案

> 文档状态：V1.0（MVP 实施基线）  
> 编写日期：2026-10-10  
> 覆盖市场：美国普通股、A 股  
> 产品定位：研究与候选池生成工具，不是自动交易系统，也不构成投资建议

## 1. 产品目标

系统要回答的不是“哪只股票最便宜”，而是：

> 哪些规模足够、经营质量较稳定、长期价值在增长的公司，当前因为合理回撤或估值收缩而进入了较有吸引力的价格区间？

核心流程是“先排雷，再逐项检查长期质量，最后判断当前价格并解释结果”。系统应具备：

- 美股和 A 股两个独立入口，各自使用适合本市场的股票池与规则；
- 可编辑、可保存的参数预设；
- 一键同步数据、一键筛选，展示进度、数据日期和异常；
- 每个入选或未入选结果都有逐项理由，不能只给一个黑盒结论；
- 支持把 MCD（McDonald's）作为美股端到端测试用例；
- 后续能做历史截面回测，而不只是拿今天的数据套历史股价；
- 不连接券商、不自动下单，第一阶段只产出观察名单。

## 2. 关键设计结论

### 2.1 全部采用硬性条件，不使用打分和权重

V1 采用可解释的 AND 筛选管线。某只股票只有在所有已启用条件上都通过，才进入最终结果；任何一项失败即不入选。系统不计算总分、不设置条件权重，也不根据主观权重排序。

条件分成三组，但三组中的已启用条件都具有同等的硬约束效力：

1. **基础排雷**：证券类型、上市年限、市值、流动性、交易状态、行业、数据完整度；
2. **公司质量**：盈利持续性、增长、现金流、资本回报、杠杆和历史回撤；
3. **估值条件**：绝对估值和历史估值百分位。

每个条件在 UI 中只有“启用 / 关闭”和阈值设置。启用后就是硬条件，不提供“仅评分”模式。结果表默认只显示全部硬条件均通过的股票；页面通过“显示未通过股票（阈值诊断）”开关保留未入选股票及失败原因，方便开发阶段观察某个阈值是否过严，后续再根据回测结果调整预设，而不是引入权重来弥补条件设计。

### 2.2 “利润不能下降”需要改写

要求十年中每一年利润都增长，会错误排除受到疫情、原材料价格或经济周期短暂影响的优质公司。建议定义为：

- 最新 TTM 归母净利润必须大于 0；
- 最近 10 个财年中至少 8 年净利润为正；
- 最近 5 年营业利润 CAGR 默认大于等于 3%；
- 最近 5 年营业利润的对数线性回归斜率大于 0；
- 最新 TTM 营业利润不低于过去 3 个完整财年的中位数的 90%；
- 收入、营业利润、自由现金流三项中至少两项长期趋势为正。

这样表达的是“增长趋势没有破坏”，而非“不允许任何一年波动”。银行、保险和 REIT 不适合这套指标，MVP 直接排除，后续建立专用模型。

### 2.3 负净资产时不能使用 ROE

大量回购会减少股东权益，成熟公司可能出现负净资产；此时 `净利润 / 平均股东权益` 得到的 ROE 没有经济解释，不能把负 ROE 当作经营差，也不能把分母很小造成的超高 ROE当作经营优秀。

规则如下：

- 平均股东权益大于 0 且 `|平均权益| / 平均总资产 >= 5%` 时，使用 ROE，默认要求 `ROE >= 10%`；
- 否则标记为 `ROE_NOT_MEANINGFUL`，不因 ROE 直接淘汰，进入“回购型公司替代路径”；
- 替代路径默认同时要求：
  - ROIC >= 10%；
  - ROA >= 5%；
  - TTM 自由现金流 > 0；
  - 自由现金流利润率 >= 5%；
  - 净债务 / EBITDA <= 3.5；
  - EBIT / 利息费用 >= 5；
  - 最近 5 年稀释后股数 CAGR <= 2%（防止一边回购、一边大量股权稀释）。

推荐口径：

```text
ROIC = NOPAT / average_invested_capital
NOPAT = EBIT * (1 - normalized_tax_rate)
invested_capital = total_debt + shareholders_equity - excess_cash
ROA = TTM_net_income / average_total_assets
FCF = operating_cash_flow - capital_expenditure
```

需在页面上明确展示“ROE 已跳过，以及采用了哪些替代指标”。MCD 就是该分支的重要回归测试对象。

### 2.4 十年最大回撤

十年最大回撤用于衡量历史最坏风险。计算使用包含拆股和现金分红影响的**总回报序列**，而非未经复权的收盘价：

```text
running_peak[t] = max(total_return_price[0:t])
drawdown[t] = total_return_price[t] / running_peak[t] - 1
max_drawdown = min(drawdown)
```

首版预设将十年最大回撤 `<= 40%` 设为硬条件。后续可根据点时回测把阈值放宽至 45%，但仍作为独立硬条件处理。

## 3. V1 筛选策略

### 3.1 股票池与基础排雷

| 维度 | 美股默认值 | A 股默认值 | 说明 |
|---|---:|---:|---|
| 证券类型 | 普通股 | 沪深主板、创业板、科创板普通股 | 排除 ETF、基金、优先股、权证 |
| 上市年限 | >= 10 年 | >= 10 年 | 允许 UI 改为 7 年，但长周期指标随之降置信度 |
| 总市值 | >= 100 亿美元 | >= 500 亿元人民币 | “不太小”的初始定义，建议按市场分别配置 |
| 20 日平均成交额 | >= 2,000 万美元 | >= 1 亿元人民币 | 避免低流动性和价格失真 |
| 交易状态 | 正常上市 | 排除 ST、*ST、退市整理、长期停牌 | 必须保留历史状态用于回测 |
| 行业 | 暂排除金融、保险、REIT | 暂排除银行、保险、券商 | 第二阶段做行业专用模型 |
| 盈利 | TTM 净利润 > 0 | TTM 归母净利润 > 0 | PE 有意义的前提 |
| 数据完整度 | 核心字段 >= 90% | 核心字段 >= 90% | 数据不足显示为未知，绝不默认为通过 |

### 3.2 估值条件

#### PE

- 当前 TTM PE：`0 < PE <= 30`；
- 若 TTM EPS <= 0，则 PE 记为无效并触发硬排除；
- PE 必须用筛选日可得的 TTM EPS 计算，不能用后来修订或尚未披露的财报；
- A 股使用归母扣非净利润计算一份辅助 PE，避免一次性收益造成“假便宜”。

#### 十年 PE 百分位

取最近 10 年每月最后一个交易日的有效 TTM PE，共约 120 个样本：

```text
pe_percentile = count(historical_pe <= current_pe) / count(valid_historical_pe)
```

默认要求 `pe_percentile <= 30%`。采用月末样本而不是所有交易日，可减少某段时间因交易日更多而被过度加权。历史 PE <= 0、缺失值和极端异常值不进入历史分布；有效样本少于 60 个月时直接判定该条件不通过。

#### 防止 PE 单指标失真

至少再计算以下三项，作为详情页解释和后续阈值研究字段：

- EV / EBIT；
- FCF yield = TTM FCF / market cap；
- 当前 PE 相对同行业的百分位。

首版只把绝对 PE 和自身十年 PE 百分位设为硬条件。行业 PE 百分位、FCF yield 和 EV/EBIT 先展示但不参与入选判断；待积累回测结果后，可以把其中某项作为新的独立硬条件启用，仍不采用加权合成。

### 3.3 长牛、增长和稳定性

建议指标及默认值：

| 主题 | 指标 | 默认判断 |
|---|---|---|
| 长期回报 | 10 年年化总回报 | >= 6% |
| 长期趋势 | 月度总回报价格对数回归年化斜率 | > 0 |
| 趋势稳定 | 最近 10 年中正收益自然年占比 | >= 60% |
| 盈利持续 | 10 年正净利润年份 | >= 8 年 |
| 增长 | 5 年营业利润 CAGR | >= 3% |
| 增长 | 5 年 FCF CAGR | >= 0%，若基期为负则改看回归趋势 |
| 毛利稳定 | 5 年毛利率标准差 | <= 5 个百分点 |
| 现金含量 | 5 年累计经营现金流 / 累计净利润 | >= 0.8 |
| 资本回报 | ROE 或替代路径 | 见 2.3 |
| 杠杆 | 净债务 / EBITDA | <= 3.5 |
| 偿债 | 利息保障倍数 | >= 5 |
| 股本纪律 | 5 年稀释后股数 CAGR | <= 2% |
| 历史风险 | 10 年最大回撤 | <= 40% |

“长牛”判断必须基于总回报，不应只看股价。对于成立不足十年的公司，V1 不纳入；不要用较短历史强行外推。

### 3.4 额外风险项

以下项目适合作为后续新增的独立硬条件。V1 数据尚未稳定覆盖的项目默认关闭，只显示风险标记；一旦用户在配置中启用，就必须满足条件才能入选，不做扣分：

- 最近财年审计意见非标准无保留；
- 最近两个季度收入与营业利润同时同比下降；
- 商誉 / 总资产过高且发生减值；
- 经营现金流连续两个财年低于净利润的 60%；
- 债务在利润下降时继续快速增加；
- 大额股份稀释；
- A 股控股股东高比例质押、监管立案、重大退市风险提示；
- 美股 10-K/10-Q 中重大持续经营疑虑、重大重述；
- 数据源之间核心财务数据差异超过容差。

新闻和文本风险在 V1 只做链接提示，不作为自动硬判据，以免自然语言误判直接改变筛选结论。

### 3.5 硬条件执行与结果结构

筛选器按由便宜到昂贵的计算顺序执行条件，但顺序不改变结论：

1. 股票池与数据完整度；
2. 市值、流动性、交易状态和行业；
3. 正利润、增长、现金流和资本回报；
4. 杠杆、偿债能力和历史最大回撤；
5. 当前 PE 和十年 PE 百分位。

默认使用“快速失败”：股票一旦确定未通过，可以停止后续昂贵计算；但在开发诊断模式下，应计算所有可计算条件，以便一次看到完整失败原因。

最终只输出：

- `all_conditions_passed`：是否通过全部已启用条件；
- `condition_results[]`：条件名、实际值、运算符、阈值、通过状态、数据日期；
- `fail_reasons[]`：所有未通过条件；
- `warnings[]`：不影响通过状态的信息性风险；
- `data_complete`：核心字段完整度是否达到 90%；
- `data_fresh`：数据是否在允许的新鲜度范围内。

`data_complete == false` 或 `data_fresh == false` 本身就是失败条件。最终结果不做全市场排名或行业排名；用户可以在表格中按任意客观字段临时排序，但排序不改变入选结论。

### 3.6 首版唯一预设阈值

开发初期只提供一个名为 `default_v1` 的预设，避免在没有回测证据时设计多个看似精确的风格预设。美股与 A 股共用质量阈值，只在市值、成交额和市场状态上有所区别：

| 条件 | 美股 `default_v1` | A 股 `default_v1` |
|---|---:|---:|
| 上市年限 | >= 10 年 | >= 10 年 |
| 总市值 | >= 100 亿美元 | >= 500 亿元人民币 |
| 20 日平均成交额 | >= 2,000 万美元 | >= 1 亿元人民币 |
| TTM PE | > 0 且 <= 30 | > 0 且 <= 30 |
| 十年 PE 百分位 | <= 30% | <= 30% |
| PE 历史有效样本 | >= 60 个月 | >= 60 个月 |
| 最近 10 年正利润年份 | >= 8 年 | >= 8 年 |
| 5 年营业利润 CAGR | >= 3% | >= 3% |
| 最新 TTM 营业利润 / 过去 3 年中位数 | >= 90% | >= 90% |
| 收入、营业利润、FCF 的 5 年正趋势 | 三项至少两项通过 | 三项至少两项通过 |
| 5 年累计经营现金流 / 累计净利润 | >= 0.8 | >= 0.8 |
| ROE（权益正常时） | >= 10% | >= 10% |
| 负/小权益替代条件 | 2.3 节所列条件全部满足 | 2.3 节所列条件全部满足 |
| 净债务 / EBITDA | <= 3.5 | <= 3.5 |
| EBIT / 利息费用 | >= 5 | >= 5 |
| 10 年总回报 CAGR | >= 6% | >= 6% |
| 十年正收益年份占比 | >= 60% | >= 60% |
| 10 年最大回撤 | <= 40% | <= 40% |
| 核心字段完整度 | >= 90% | >= 90% |
| 行情数据新鲜度 | <= 7 个自然日 | <= 7 个自然日 |
| 财务数据新鲜度 | 已包含截至运行日应披露的最新一期 | 已包含截至运行日应披露的最新一期 |

此外，美股排除银行、保险、REIT、BDC、ADR 和有限合伙；A 股排除银行、保险、券商、ST、*ST、退市整理及长期停牌证券。表中每一行以及对应市场排除项都是硬条件。开发过程中若发现数据定义或覆盖不足，应通过修改 `default_v1` 的版本产生 `default_v2`，不得静默改变旧预设。

#### 2026-10-10 免费数据全量校准

使用 `free_online` 数据源和未修改的 `default_v1` 进行一次完整实测：

| 市场 | 基础候选数 | 最终入选数 | 数量目标 |
|---|---:|---:|---:|
| 美股 | 421 | 4 | <= 30 |
| A 股 | 161 | 0 | <= 15 |

美股入选为 ITW、KO、LECO、MCD。可见当前预设已经满足数量目标，且 A 股甚至偏严；页面此前显得“结果很多”，实质上是把基础候选和被淘汰样本默认展示在结果表中，并非硬条件放得过宽。因此本轮不改动阈值，避免对一次免费数据截面过拟合，只修正展示口径。该数量会随价格、财报和免费接口覆盖变化，30/15 是校准告警线，不是 Top-N 截断规则。

## 4. 美股与 A 股的差异化处理

### 4.1 美股

- 以 SEC CIK 作为公司主标识，ticker 只是会变化的展示标识；
- 财务事实优先使用 10-K/10-Q 的披露日期和 period end，保留原始 XBRL tag、form、filed date；
- 同一事实可能因修订或不同 XBRL tag 重复，规范化层必须制定取值优先级；
- ADR、有限合伙、BDC、REIT、银行等先从通用股票池排除；
- 总回报序列要正确处理拆股、特别股息和 ticker 变更。

### 4.2 A 股

- 以带交易所后缀的代码为标识，如 `600519.SH`、`000001.SZ`；
- 财务数据保留 `ann_date` 与 `end_date`，筛选日只能使用当时已经公告的数据；
- 利润优先使用归母净利润，并额外计算扣非归母净利润趋势；
- 价格使用后复权或自行构造总回报指数；不要在跨股票比较时直接使用前复权绝对价格；
- 处理送转、分红、配股、停牌、涨跌停、ST 状态和上市板块；
- 回测股票池必须包含当时已退市股票和当时的 ST 状态，否则产生幸存者偏差。

## 5. 数据源方案

### 5.1 推荐的 MVP 组合

#### V1 已实现的免费模式

为了做到无需付费账号即可运行，当前 V1 实际采用以下组合：

- 美股基础候选与十年行情：Yahoo 公开接口（通过 yfinance，仅限个人研究）；
- 美股财报：SEC EDGAR Company Facts 官方接口；
- A 股基础候选与十年行情：Yahoo 公开接口；
- A 股财报：新浪公开财务报表（通过 AKShare）；
- 同步时先在远端按市场、市值、PE 和非金融/非房地产行业预筛，再对候选逐只计算十年指标；
- 原始行情和财报响应缓存在 `data/cache/`，避免反复请求。

免费模式没有商业数据源 SLA。历史 PE 使用财报披露后可得的年度 EPS 构造月度序列，是可复现的免费近似口径，并非商业数据商的逐日标准化 TTM PE。页面中的“基础候选数（非结果数）”是通过基础预筛并进入本地详细计算的数量，不代表最终入选数或交易所全部上市证券数。Massive、Tushare Pro 等仍保留为后续提高稳定性和口径精度的升级选项。

#### 美股

1. **财报主源：SEC EDGAR Data APIs**  
   免费、权威，提供 submissions 和 XBRL company facts。SEC 明确提供公开 API，但自动访问要遵守其 Fair Access 与隐私安全政策；实现时设置明确的 `User-Agent`、限速、缓存和重试。官方入口：[SEC data APIs](https://data.sec.gov/) 与 [SEC filing search / API 说明](https://www.sec.gov/search-filings)。
2. **行情主源：Massive（原 Polygon.io）或同等级商业源**  
   官方接口支持美股历史聚合行情、公司行动和标识数据。当前免费层历史深度有限，而 10 年回撤需要相应历史套餐或另一个授权数据源；具体套餐在实施时再次核价。[Massive Stocks API](https://www.massive.com/stocks)、[REST stocks overview](https://massive.com/docs/rest/stocks/overview)。
3. **财务规范化备选：Alpha Vantage / Massive Financials**  
   Alpha Vantage 提供年报、季报资产负债表、利润表与现金流量表，并说明其字段映射到 GAAP/IFRS taxonomy；适合快速验证，但仍需和 SEC 原文抽样核对。[Alpha Vantage API 文档](https://www.alphavantage.co/documentation/)、[字段映射说明](https://documentation.alphavantage.co/FundamentalDataDocs/index.html)。Massive 的财务字段目前属于额外付费能力，覆盖始于 2009 年左右，可作为减少自建 XBRL 清洗成本的商业选项。[Massive financials fields](https://massive.com/knowledge-base/article/what-fields-can-i-expect-from-massives-financials-api)。

#### A 股

1. **主源：Tushare Pro**  
   `stock_basic`、`daily`、`adj_factor`、`daily_basic`、`income`、`balancesheet`、`cashflow`、`fina_indicator`、`dividend`、`fina_audit` 可覆盖 MVP。其财务与行情接口按积分分级，应在开发前确认账号权限。官方目录显示财务报表与财务指标随财报更新；`daily_basic` 可按日获取 PE、PB、市值等字段。[Tushare 数据目录](https://tushare.pro/document/1?doc_id=108)、[daily_basic 文档](https://tushare.pro/document/2?doc_id=32)。
2. **开发校验源：AKShare**  
   可用于原型和跨源抽查，但大量接口依赖上游网站页面，字段和可用性可能变化，不建议作为唯一生产主源。
3. **长期生产选项：有授权的 Wind、Choice、聚宽/JQData 等**  
   当需要严肃点时回测、退市股票、历史成分和稳定 SLA 时再评估。购买前必须确认本地存储、展示、派生指标和再分发许可。

### 5.2 数据源原则

- 原始响应按日期不可变落盘，规范化数据可重建；
- 每个字段记录 `source`、`as_of_date`、`period_end`、`filing_date`、`ingested_at`；
- 不把网页抓取或非官方 Python 包的返回结构当作稳定契约；
- 不在浏览器端放 API key；密钥只从服务端环境变量读取；
- 上线前逐条审阅数据商许可，特别是缓存期限、展示和再分发条款；
- Yahoo Finance/yfinance 可用于个人原型人工核对，不作为生产唯一来源；
- 市场数据延迟不会显著影响日频筛选，MVP 不需要实时行情。

## 6. 技术实现规划

### 6.1 推荐技术栈

MVP 采用单机、日频、本地优先架构：

- Python 3.12；
- Streamlit：参数表单、两个市场按钮、结果表和详情页；
- Polars/Pandas：指标计算；
- DuckDB + Parquet：本地分析存储；
- Pydantic：配置和数据模型校验；
- httpx + tenacity：数据下载、限速与重试；
- Plotly：PE 历史带、总回报与回撤图；
- pytest：公式、数据适配器、MCD 回归和点时回测测试；
- Ruff + mypy：代码质量。

Streamlit 足以最快交付当前的单用户工具。若以后需要多人、权限和长任务，再保留计算核心不变，将 UI 升级为 React，后端换成 FastAPI，任务队列用 Celery/RQ。

### 6.2 逻辑架构

```text
数据源
  -> adapters（下载、限速、原始快照）
  -> normalization（统一标识、会计口径、公司行动）
  -> point_in_time_store（按披露日可见的数据）
  -> metrics（PE、ROIC、增长、总回报、回撤）
  -> rules（逐项硬条件、数据有效性、解释）
  -> screen_runs（冻结本次参数、数据版本和结果）
  -> Streamlit UI / CSV 导出
```

### 6.3 核心数据表

- `securities`：内部 ID、市场、ticker、CIK/ts_code、证券类型、上市/退市日期、行业；
- `security_identifier_history`：ticker 与公司标识的生效区间；
- `prices_daily`：OHLCV、复权因子、总回报价格、来源；
- `corporate_actions`：拆股、股息、配股、送转；
- `financial_facts_raw`：原始 tag、值、单位、期间、披露时间、来源；
- `financial_statements_normalized`：收入、EBIT、净利润、现金流、资产负债等标准字段；
- `metrics_daily`：筛选日的所有派生指标及质量标记；
- `screen_configs`：版本化参数 JSON/YAML；
- `screen_runs`：运行 ID、市场、as-of date、数据版本、配置哈希、状态；
- `screen_results`：整体通过状态、逐项条件结果、失败理由和警告。

金额字段必须同时存货币，不要直接把美元和人民币混合比较。美股和 A 股始终分别运行、分别展示。

## 7. UI 方案

### 7.1 页面布局

左侧参数栏：

- 预设选择：首版默认 `default_v1` / 自定义；
- 股票池、市值、上市年限、流动性；
- 估值、增长、质量、杠杆、回撤参数；
- 每个条件的启用状态和阈值；启用即为硬条件；
- “恢复默认”“保存为新预设”。

主页面顶部：

- 数据截至日期、最近同步时间、数据源状态；
- **同步美股数据**、**开始筛选美股**；
- **同步 A 股数据**、**开始筛选 A 股**；
- 默认同步与筛选分成两个按钮，避免每次改参数都重新下载数据；
- 运行期间展示阶段、进度、成功/失败证券数，按钮防重复点击。

结果区域：

- 默认只展示通过全部硬条件的最终入选股票，美股目标上限为 30 只、A 股目标上限为 15 只；
- 超过目标上限时给出告警，但不得用评分、权重或 Top-N 截断结果；应结合条件分布重新校准硬阈值；
- 未通过股票默认隐藏，可通过“显示未通过股票（阈值诊断）”开关查看；
- 表格列：代码、名称、行业、市值、PE、十年 PE 百分位、ROE/ROIC、5 年增长、十年最大回撤、通过状态、失败条件数；
- 支持按行业、通过状态过滤和 CSV 导出；不提供分数列；
- 点击股票展开详情：十年总回报图、回撤图、PE 历史带、利润/FCF 趋势、资产负债表摘要；
- “为何入选/为何淘汰”逐条显示实际值、阈值、通过状态和数据日期；
- 对负权益公司显示“ROE 不适用，已启用替代路径”的醒目标识。

### 7.2 错误体验

- API 配额不足、某股票缺字段、整批同步失败要区分；
- 部分失败时继续筛选其他证券，结果页列出失败清单；
- 禁止把 `null` 转成 0；
- 过期数据必须显示黄色警告，超过设定天数默认不允许生成“最新筛选”；
- 每次运行可复现：保存参数版本、代码版本、数据快照日期和运行日志。

## 8. MCD 测试设计

MCD 不应被写成“永远必须入选”的固定答案，因为价格和 TTM 数据会变化。它应是一个**机制测试用例**：保证系统能正确处理成熟、稳定、长期回购且可能为负账面权益的公司。

### 8.1 固定快照测试

在 `tests/fixtures/mcd/` 保存一个注明来源和 `as_of_date` 的小型冻结数据集：

- 10 年月度总回报序列；
- 10 年财年及最近季度财务字段；
- 股数、分红、拆股、债务、利息、现金；
- 当前筛选日价格；
- SEC CIK 与 ticker 映射。

必须验证：

1. ticker 能稳定映射到公司，不因 ticker 作为主键造成错配；
2. 负或过小股东权益时 `roe_status == ROE_NOT_MEANINGFUL`；
3. 系统进入 ROIC/ROA/FCF/杠杆替代路径，而非因 ROE 为负直接淘汰；
4. PE 使用筛选日前已披露的 TTM EPS；
5. 十年 PE 百分位只使用当时可见数据；
6. 十年最大回撤公式结果和手工样例一致；
7. 页面完整显示通过项、失败项与警告；
8. 改动 PE 或回撤阈值会可预测地改变 MCD 结果。

### 8.2 在线集成测试

在线测试只检查 SEC/行情适配器仍能返回符合 schema 的数据，不断言“今天的 MCD 必须通过”。这样不会因市场价格自然变化导致 CI 随机失败。

## 9. 回测方法

回测是第二阶段，但数据模型从第一天就必须支持 point-in-time：

- 每月最后一个交易日运行一次筛选；
- 财报仅在实际披露日之后可用，并增加 1 个交易日的保守延迟；
- 使用当时存在的股票池、ticker、行业、ST 和退市状态；
- 次日开盘或下一月首个交易日成交，加入手续费和滑点；
- 持有 12 个月或月度再平衡，分别测试；
- 与 S&P 500 / 沪深 300 的总回报比较；
- 报告 CAGR、波动率、最大回撤、Sharpe、Sortino、胜率、换手率以及行业暴露；
- 做参数敏感性分析，例如 PE 上限 25/30/35、百分位 20%/30%/40%、最大回撤 40%/45%/50%；
- 保留未通过公司，检查被过滤后的机会成本；
- 不以调参后最好的一组作为唯一结果，划分开发期与样本外验证期。

最容易犯的错误是用今天的财务指标、今天仍上市的公司去回测十年前，这会同时引入未来函数和幸存者偏差。

## 10. 迭代计划与验收标准

### 阶段 0：数据可行性验证（2～4 天）

- 选 MCD 与 5 只 A 股样本；
- 验证 10 年价格、公司行动、财报字段和披露日期可得性；
- 输出字段覆盖率与数据源成本表；
- 决定美股 10 年行情最终供应商。

验收：MCD 及 A 股样本的核心指标可手工复核，缺失字段有明确处理方案。

### 阶段 1：单股指标引擎（约 1 周）

- 建立 schema、DuckDB/Parquet、配置模型；
- 完成估值、增长、ROE 替代路径、总回报和回撤计算；
- 实现 MCD 固定快照单元测试。

验收：所有公式测试通过；任一指标可追溯到源字段、期间和披露日。

### 阶段 2：批量筛选与 UI（约 1～2 周）

- 接入美股和 A 股适配器；
- 完成两个市场按钮、参数编辑、进度、结果详情和导出；
- 保存可复现的 screen run；
- 部分失败不影响整批结果。

验收：在目标机器上从空缓存完成一次两市场同步与筛选；页面能解释每只股票的去留。

### 阶段 3：质量强化（约 1 周）

- 跨源抽查、异常值检测、数据新鲜度告警；
- 审计意见、A 股风险标记、股本稀释等；
- 性能优化和增量更新。

验收：核心字段覆盖率 >= 90%，异常和过期数据不会静默进入结果。

### 阶段 4：点时回测（2～4 周，取决于授权数据）

- 历史股票池与退市数据；
- 月度横截面和基准；
- 参数敏感性及样本外验证。

验收：给定数据版本和配置哈希可完全复现回测，报告明确披露数据偏差与成本假设。

## 11. 主要风险与边界

- **会计口径风险**：不同公司 XBRL tag 与重述会造成表面可比、实际不可比；需保留原始事实和映射版本。
- **行业差异**：通用 ROIC、净债务/EBITDA 不适合金融和部分 REIT；V1 直接排除这些行业。
- **估值陷阱**：低 PE 与大回撤可能来自永久性基本面恶化；所以增长、现金流和负债必须先过关。
- **数据授权**：可访问不等于可长期存储或展示；生产数据源必须审阅许可。
- **历史偏差**：退市数据、披露时间和公司行动处理不完整会显著美化回测。
- **参数过拟合**：MCD 只能验证机制，不能围绕一只股票反向调参数。
- **结果时效**：这是日频研究系统，不适合作为盘中成交信号。
- **决策边界**：系统用于缩小研究范围；入选后仍需阅读财报、理解竞争优势、管理层资本配置与特定风险。

## 12. 建议立即采用的 MVP 默认策略

第一版按以下顺序实施：

1. 排除不支持行业、上市不足十年、小市值、低流动性、负 TTM 利润和核心数据不足公司；
2. 强制 `0 < PE <= 30` 且十年月度 PE 百分位 <= 30%；
3. 要求 10 年至少 8 年盈利、5 年经营利润趋势向上、累计经营现金流/净利润 >= 0.8；
4. 正常权益公司要求 ROE >= 10%，负/小权益公司启用 ROIC/ROA/FCF/杠杆替代路径；
5. 十年最大回撤 <= 40%；
6. 仅输出通过全部已启用条件的股票，不计算总分或综合排名；未通过股票保留逐项失败原因；
7. 美股先用 MCD 固定快照打通全链路，再扩展股票池；A 股用 5～10 只跨行业大盘股做同样验证；
8. 第一版不做自动交易、不做新闻情绪硬过滤、不支持金融行业专用模型。

这套默认值应被视为可验证的起点，而不是永恒参数。真正上线前，应通过点时回测、样本外验证和人工财报复核决定是否调整阈值。
